## 3. 에뮬레이터가 안 뜨던 진짜 이유

인수인계서는 macOS의 adb 데몬 문제를 P0로 적어뒀지만, 이 PC(Windows)에서 adb는 정상이었습니다.
증상은 같아 보여도 원인이 완전히 달랐습니다.

**1) Windows 사용자명이 한글이라 파일을 못 엽니다**

에뮬레이터가 시스템 이미지의 AVB 파라미터 파일을 읽지 못했습니다. 파일은 356바이트로 멀쩡히 존재합니다.

```
Could not open C:\Users\사용자\…\VerifiedBootParams.textproto: Unknown error
```

**2) 게스트가 /system 검증에 실패합니다**

부팅 파라미터에 다이제스트가 비어서 전달됩니다.

```
[libfs_avb] Invalid hash size:
[libfs_avb] Failed to verify vbmeta digest
init: Failed to mount /system
```

**3) 커널이 패닉하고 재부팅합니다 — 83회**

```
Kernel panic - not syncing: Attempted to kill init!
```

매번 3.9초 근처에서 죽고 다시 시작합니다. adb가 계속 `offline`이던 건 게스트가 adbd까지 간 적이
아예 없었기 때문입니다.

### 해결: ASCII 경로 junction

SDK를 옮기지 않고 ASCII 경로 링크를 만들어 우회했습니다. 실제 파일과 기존 AVD는 그대로 둡니다.

```
C:\AndroidSdk  →  C:\Users\사용자\AppData\Local\Android\Sdk
C:\AndroidAvd  →  C:\Users\사용자\.android\avd
```

| | 한글 경로 | ASCII junction |
|---|---|---|
| AVB 경고 | 발생 | 없음 |
| 커널 패닉 | 83회 | 0회 |
| 부팅 사이클 | 83회 루프 | 1회 |
| adb 상태 | 영구 offline | device |

**이 PC에서 안드로이드 도구를 쓸 때는 반드시 `C:\AndroidSdk` 경로로 실행해야 합니다.**
한글 경로로 직접 실행하면 같은 증상이 재발합니다.

배제하는 데 시간이 걸린 것들도 적어둡니다. 시스템 이미지 손상, SDK 버전 불일치, 메모리 부족,
하이퍼바이저, adb 자체는 **모두 원인이 아니었습니다.** 서로 다른 시스템 이미지 2개가 똑같이
실패한 것이 결정적 단서였습니다 — 둘 다 같은 한글 경로 아래 있었기 때문입니다.

## 4. 기기에서만 드러난 앱 결함

세 건 모두 **실기에서 앱을 띄우기 전에는 발견될 수 없는** 종류입니다. 지금까지 Android 실제
구동 검증을 한 번도 못 했기 때문에 남아 있었습니다.

### 4-1. 앱이 시작하자마자 죽음 — Firebase Auth 초기화 실패 `P0` `수정·병합`

**증상**

```
ERROR [Error: Component auth has not been registered yet]
  initializeAuth (@firebase/auth/dist/rn/index.js)
  <global> (src/services/firebase.js)
```

**원인**

firebase 10은 `@firebase/auth`에만 `react-native` 조건을 갖고 `@firebase/app`에는 없습니다.
Expo 54가 Metro의 package exports를 켜면서 두 패키지가 서로 다른 빌드로 해석됐고,
**컴포넌트 레지스트리가 둘로 쪼개졌습니다.** `initializeApp`이 등록한 곳과 `initializeAuth`가
찾는 곳이 달랐던 겁니다.

**수정**

```js
// metro.config.js
config.resolver.unstable_enablePackageExports = false;
```

레거시 `react-native` 필드 해석으로 되돌려 두 패키지가 같은 인스턴스를 보게 합니다.

**영향** — 이 한 줄이 없으면 **어떤 기기에서도 앱이 시작 즉시 종료됩니다.**

### 4-2. 온보딩 마지막에 "프로필 저장에 실패했어요" `P0` `수정·병합`

**원인**

생년월일이 자유 입력 칸이고 **숫자 키보드**로 열립니다. 그래서 `20000730`처럼 하이픈 없이
치는 게 자연스러운데, 그 값이 가공 없이 서버로 갑니다. 서버는 `LocalDate`로 바인딩하므로
파싱에 실패해 400을 돌려줍니다.

화면 검증은 "비어 있지 않음"만 봤기 때문에, 실패가 **온보딩 4단계를 다 끝낸 뒤에야** 드러나고
어느 값이 문제인지도 알려주지 않았습니다.

**수정**

- 입력하는 동안 하이픈을 자동으로 넣습니다 — `20000730 → 2000-07-30`
- 달력에 없는 날짜와 미래 날짜를 화면에서 먼저 막습니다. 서버의 `requireNotFuture`와 같은 기준입니다
- 요청 본문에도 유효한 ISO 날짜만 싣습니다 — 화면을 우회하는 경로가 생겨도 잘못된 값이 못 나갑니다
- 회귀 방지 케이스를 `onboardingStore.check.mjs`에 추가했습니다

```
거부되는 값  11112233 · 1111-22-33 · 2000-02-30 · 2099-01-01 · 2000-7-3
```

### 4-3. 로그인 버튼이 스피너에서 안 풀림 `P1` `미수정`

`app/auth/login.jsx`에서 `busy`를 되돌리는 경로가 `catch`뿐입니다. 성공하면 화면이 언마운트된다는
전제인데, **이미 같은 계정으로 로그인된 상태에서 다시 로그인하면** `onAuthStateChanged`가 상태
변화를 알리지 않는 경우가 있습니다. 그러면 라우팅도 안 되고 `busy`도 안 풀려 버튼이 영영
스피너로 남습니다.

이번 E2E를 막지는 않아 손대지 않았습니다. 고칠 방향은 **성공 경로에서도 `busy`를 풀고,
이미 인증된 경우 `bootstrap()`을 직접 호출**하는 것입니다.

## 5. E2E 결과

실제 Firebase 계정으로 회원가입부터 그룹 활성화까지 갔습니다. 아래는 DB에 남은 실제 기록입니다.

| # | 사용자 | 거래 | 증감 | 결과 |
|---|---|---|---:|---|
| 7 | USER A | INITIAL_GRANT | +3 | 온보딩 완료 → 하트 3 |
| 8 | USER A | GROUP_JOIN_SPEND | −1 | 그룹 생성 → 2 |
| 9 | USER A | GROUP_JOIN_REFUND | +1 | 시작 전 취소 → 3 |
| 10 | USER A | GROUP_JOIN_SPEND | −1 | 새 그룹 생성 → 2 |
| 11 | USER B | INITIAL_GRANT | +3 | 온보딩 완료 → 하트 3 |
| 12 | USER B | GROUP_JOIN_SPEND | −1 | 참가 → 2 |

최종 상태는 **그룹 `ACTIVE`**, 두 참여자 모두 `ACTIVE`, 지갑 잔액 각 2입니다. 정원 2/2가 채워지는
순간 서버가 같은 트랜잭션에서 `FULL → ACTIVE`로 전이시켰습니다.
**프론트가 하트를 계산하거나 상태를 바꾼 곳은 없습니다.**

> **혼자서는 루틴 진행 화면까지 갈 수 없습니다.**
> 서버는 정원이 다 찼을 때만 그룹을 활성화하는데, 생성 화면의 정원 하한이 2입니다
> (`create.jsx`의 `Math.max(2, …)`). 백엔드 자체는 1인 그룹을 지원하므로, 테스트 편의를 위해
> 하한을 1로 낮출지는 **제품 결정이 필요합니다.** 임의로 바꾸지 않았습니다.

### 아직 확인하지 못한 것

- **사진 인증** — `VERIFICATION_MEDIA_ENABLED=false`라 `upload-intent`가 503입니다. 버그가 아니라
  의도된 배포 게이트이고, 프론트도 이를 "인증 실패"가 아닌 `unavailable`로 구분해 표시합니다.
  S3 버킷·리전·IAM이 준비돼야 진행됩니다.
- **Progress · AI Coach 화면** — 그룹이 방금 ACTIVE가 된 시점에서 테스트를 종료했습니다.
- **세션 복원 · 로그아웃** — 앱 재시작 시 세션이 유지되는 것은 확인했으나(온보딩 화면으로 바로
  복귀), 전체 시나리오는 돌리지 않았습니다.
- **실제 AI provider 호출** — 유료 호출은 하지 않았습니다.

## 7. 다른 PC에서 재현하려면

이번에 세팅하면서 걸렸던 것들입니다. 코드는 공유되지만 로컬 환경은 공유되지 않습니다.

- **사용자명이 한글이면** Android SDK와 AVD 경로에 ASCII junction을 만들고 그 경로로 실행하세요. 3번 항목 그대로입니다.
- **Java 21**은 설치돼 있어도 `JAVA_HOME`이 비어 있으면 `gradlew`가 실패합니다. 인수인계서에 이 단계가 빠져 있었습니다.
- **프론트 `.env`** 는 저장소에 없습니다. Firebase 값은 `google-services.json`에서 옮기면 되고,
  **백엔드 `FIREBASE_PROJECT_ID`와 같은 프로젝트여야 합니다.**
- **에뮬레이터에서 백엔드 주소**는 `http://10.0.2.2:8080`입니다. `localhost`는 기기 자신을 가리킵니다.
- **Expo Go가 Metro에 못 붙으면** `adb reverse tcp:8081 tcp:8081` 후 `exp://127.0.0.1:8081`로 열면 됩니다. LAN IP로는 붙지 않았습니다.
- **`google-services.json`** 이 백엔드 저장소에 추적되지 않은 채 놓여 있었습니다. 이번에 `.gitignore`에 추가했습니다.
